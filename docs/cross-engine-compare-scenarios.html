Stage 0 — runs in every scenario, first

Pull ~100 rows into memory from both sides (sampled by key from the source, same keys fetched from the target), hash each row with hashlib.sha256 in Python, and confirm it equals both the Oracle STANDARD_HASH pushdown and the Snowflake SHA2 pushdown — per column type. This is the gate:

  1. Validates the encoding contract — if any engine's pushed-down hash ≠ the in-memory hash, the canonical SQL for some type is wrong; stop before trusting a full pushdown.
  2. Estimates divergence — decides which full strategy runs next (recursive bucket vs streamed merge vs sampled verdict).

The “Sample-gate catches it?” column below is the honest scorecard: Stage 0 is a strong gate for systematic and encoding faults, but by construction it cannot find sparse, rare-row, or timing faults — those are exactly what the full compare (Stage 1+) exists to catch.
